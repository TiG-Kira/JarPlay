### 2. 画面不铺满 / 黑屏 Bug（核心）
根因（三层叠加）：
1. `ProfileModel` 的无参构造**不写任何默认值**，而 Gson 反序列化走这个构造；`config.json` 缺失字段时残留 Java 0 值：
   - `ScreenScaleType = 0`（不缩放）→ 画面按 240x320 原始像素绘制在角落；
   - `ScreenGravity = 0`（靠左）→ 贴在左上；
   - `ScreenBackgroundColor = 0` → `setBackgroundColor(0)` 得到纯黑背景。
2. `ConfigDetailScreen`（旧 Compose 版）用 `mutableStateOf(ProfileModel())` 作初值并在 `onDispose` 无条件保存，加载竞态时会把全 0 配置写回磁盘。
3. `Canvas.updateSize()` 对 `scaleRatio <= 0` 没有兜底（会算出 0 尺寸）。

修复：
- `ProfileModel`：VERSION 3→4；无参构造与 `ProfileModel(File)` 统一调用 `applyDefaults()`；新增 `SCALE_TYPE_*` / `GRAVITY_*` 常量、`normalize()`、`defaults(dir)`、`copy()`；默认 `screenScaleType = SCALE_TYPE_FILL(2)`、`screenGravity = CENTER(2)`、`screenBackgroundColor = 0xD0D0D0`。
- `ProfilesManager.loadConfig`：新增 `case 3:` 迁移（`ScreenScaleType==0` → 2、`ScreenBackgroundColor==0` → 默认灰），所有分支末尾调用 `normalize()`；case 2 旧版「不缩放」改为等比缩放。
- `Canvas`：静态默认值改为 `scaleRatio=100 / scaleType=1 / screenGravity=2`；`updateSize()` 增加显示尺寸为 0 的兜底、`scaleRatio<=0` 兜底、等比缩放改用 `min(宽比, 高比)` 统一公式、`onWidth/onHeight` 至少为 1。
- `ConfigDetailScreen`：初值改为 `null`（加载完成前显示"正在读取设置…"），`onDispose` 仅在非 null 时保存；FAB「启动」前先保存。

### 5. 验证受限（不要再在本机尝试编译）
本机**无法**完成 Gradle 编译验证，实测过程：
- `cmd.exe` 被工具安全策略拦截；`services.gradle.org` 下载发行版 0 字节。
- Git Bash 下 `sh gradlew` 会 classpath 被破坏 → `ClassNotFoundException: GradleWrapperMain`；
  正确姿势是直接 `java -classpath "<repo>/gradle/wrapper/gradle-wrapper.jar" org.gradle.wrapper.GradleWrapperMain ...`。
- 换独立 `GRADLE_USER_HOME` 到**短路径**（如 `D:/gh`，长路径触发 Windows MAX_PATH），
  并用 `_winapi.CreateJunction` 把 `wrapper` 与 `caches/modules-2` junction 过去可复用缓存。
- 但 Gradle 全程在 artifact transform 阶段对 `caches/<ver>/transforms/<hash>/<hash>.lock`
  报「拒绝访问」（python 可正常创建同名文件），每次随机 2~130 个 hash，重跑能逐步推进任务。
- 循环重跑（每次约 2 分钟）推进到的**最远位置**是 `:app:compileOpenDebugKotlin`：
  `:app:generateOpenDebugResources` / `mergeOpenDebugResources` / `packageOpenDebugResources`
  等资源任务全部通过（→ 新增的布局 XML、strings.xml、drawable 引用语法有效），
  但 Kotlin 编译任务本身仍因上述文件锁问题 FAILED，**没有产生任何 Kotlin 编译诊断**。
- 结论：**Kotlin 源码是否可编译仍未验证**，需要在 Android Studio 里编译确认。
  用户已明确要求不要再循环尝试编译。

### 3. 安卓图标导出方案（可复用）
脚本：`jarplay-logo-design/export_icons.py`（Pillow，环境 `C:\Users\Kira\.workbuddy\binaries\python\envs\default`）。

关键做法与踩坑：
1. **从位图反推几何**：按非白像素求包围盒裁出圆角方块；扫描第 0 行首个深色像素的位置得到圆角半径（实测 99px / 707px = 14%）；用超采样 `rounded_rectangle` 生成抗锯齿 alpha 遮罩，得到透明四角的圆角方块版本。
2. **底色校准**：生成图底色是 `#1A2437`，与品牌色 `#0E1430` 差 16 个通道值，用 `ImageChops.difference` + 阈值做区域替换校准回品牌色（差值 >4 才做）。
3. **符号层裁切的坑**：直接用「与底色差值」当 alpha，方块**外缘的抗锯齿像素**差值极大，会被误判成符号，导致 bbox = 整块方块（前景层被错误放大到 100%）。修正办法：先按内缩的圆角内区（pad = radius/8）裁剪，再求 bbox。修正后符号组 454×379，占 64.2%。
4. **自适应图标前景层**：符号按 `mark宽/方块宽` 的比例放进 108dp 画布居中，实测 alpha bbox 277/432 = 64.1%，落在 72dp 安全区内。
5. **单色层（安卓 13+ 主题图标）**：不能用彩色前景，否则三角会与罐体糊成一个剪影。改为只取琥珀色像素当 alpha（白三角自然成为镂空），得到「罐体剪影 + 三角镂空」。同时把 `mipmap-anydpi-v26/ic_launcher.xml` 的 `<monochrome>` 从 `@mipmap/ic_launcher_foreground` 改指 `@mipmap/ic_launcher_monochrome`。
6. **Play 商店 512** 要**满幅**（四角填品牌色，不留透明）；legacy `ic_launcher.png` 才是透明四角的圆角方块。两者不能混用。
7. 旧资源已备份到 `android-export/_backup_old_icons/`；脚本可重复运行（备份步骤有「目标已存在则跳过」保护，避免二次运行覆盖真实备份）。

- 图片生成/编辑会随机在**右下角烙上「AI生成 WORKBUDDY」水印**（同一批里时有时无）。文字/水印清除用 `buddy-image-processing` 的 `erase`（`buddy-image-processing.py image-edit --operation erase`），单张约 50s–2min，需先 `connect_cloud_service` 取 token，结果落在**项目根目录**的 `processed_image_*.png`，要记得移走。
