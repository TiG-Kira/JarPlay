## CI 平台解析问题终局解决（第 17-22 次 run，2026-10-22 下午）
- **根因**（第 17 次 run 的 --info 日志实锤）：AGP 平台自动安装/license 走旧预装 SDK
  `C:\Program Files (x86)\Android\android-sdk`，而 initTarget 查 `C:\Android\android-sdk`
  （双 root 分裂）；且远端仓库只有新命名 `platforms;android-37.0`，AGP 9.1 按 hash
  `android-37` 查找。文件系统 hack（rename+伪造 package.xml/source.properties）在
  runner 上始终不被 AGP target 加载器接受（本地 cisdk4b 成功是假象/不同代码路径）。
- **终局方案**：AGP 9.0+ 新 compileSdk DSL —— 根 build.gradle
  `COMPILE_SDK_MAJOR = 37, COMPILE_SDK_MINOR = 0`，两模块
  `compileSdk { version = release(COMPILE_SDK_MAJOR) { minorApiLevel = COMPILE_SDK_MINOR } }`，
  AGP 直接按 `android-37.0` 解析 → CI 原生安装 `platforms;android-37.0` 即可，
  全部 hack 删除。本地验证：隐藏 hack android-37 只留原生 37.0 后 BUILD SUCCESSFUL。
- **其它新知**：
  - Windows runner 双 SDK：C:\Android\android-sdk（ANDROID_HOME）+ C:\Program Files (x86)\Android\android-sdk（旧预装，含全套 build-tools/NDK/platforms）。
  - Git Bash 调 .bat + 带空格路径会把 'C:\Program' 拆开 → 需 8.3 短路径（cygpath -d）。
  - python 经 Bash heredoc 传 `\` 会被 JSON 转义层吃掉（`\a`→响铃符），路径字符串易损坏，改用 Write 工具写脚本。
  - AGP 9.1 官方支持表述即「API 级别 37.0」，AGP 9.0 引入新 compileSdk/targetSdk DSL。
- **CI 状态**：run 39785377727（第 22 次）Debug 冒烟全绿；release workflow 已改为
  checkout 默认分支（tag 仅作上传目标）+ `gh workflow run -f tag=v1.0.1` 手动触发中。
- **排障教训**：本地实验环境单 SDK root、无 (x86) 残留，无法代表 runner；--info 才是破案关键。
