## v1.0.3：三项 UI 修复（底栏玻璃 / 顶栏折叠 / 关于页文案）

### 1. 玻璃底栏「深色板块」
- 根因：MainActivity 内容层只有 `miuixLayerBackdrop`，没有不透明底色 → 底栏下方空白区折射到窗口底色，
  呈现中灰板块（用户截图实测 #5f5f5f）。
- 修法：内容层 Box 改为 `.fillMaxSize().background(MiuixTheme.colorScheme.background).miuixLayerBackdrop(glassBackdrop)`。
- AVD 实测：底栏区域均值 243，栏外 247，无暗块（此前截图为 95）。

### 2. 主页/关于页顶栏不折叠
- 根因：`MiuixScrollBehavior()` 全默认 → 不跟踪滚动；必须显式 `canScroll = { true }`。
- 坑：`MiuixScrollBehavior` 是 **@Composable 工厂**，写进 `remember { }` 会编译失败，
  参数用 `remember` 固定即可。MainActivity 与 AboutActivity 都改了。
- AVD 实测：设置页标题 `[78,312][270,451]`(139px 大标题) → 滚动后 `[580,191][700,278]`(87px 居中)。

### 3. 关于页文案
- 错文本：「检查更新」行副标题误用 `about_message`（整段应用简介），改为 `about_check_updates_desc`。
- `UpdateResult.CheckFailed` 标题/副标题都错显示成 `up_to_date`，新增 `check_failed` 串（中英都加）。
- `about_message` 里残留字面量 `<BR>` 已删。
- 脚本比对 values vs values-zh-rCN，补齐 22 条缺失中文（up_to_date/app_deleted/edit_keyboard/
  exit_edit_mode/error_no_picker/show/download_failed/install_failed/response_body_empty/
  apk_download_failed/request_install_permission_failed/download_failed_with_code 等）。
- 版本 versionCode 3→4、versionName 1.0.2→1.0.3（open 变体实际 1.0.3-open）。

### AVD 验证环境备忘

## v1.0.4：用户实机反馈的 6 项修复（AVD 逐项实测）

### 1. 玻璃底栏在应用页完全消失（取景层语义）
- 关键认知：`miuixLayerBackdrop` 捕获的是**该节点绘制的内容**，节点自身的
  `background()` 修饰符不在被捕获范围内。所以只在修饰符上铺主题底色无效 ——
  只有被卡片挡住的位置玻璃才渲染得出来，一离开卡片就整块消失。
- 正确做法：在取景 Box **内部**放一个铺满的 `Box(Modifier.fillMaxSize().background(theme bg))`
  作为第一个 child。
- AVD 实测：应用页空态 y=2700 非背景像素 0 → 718，y=2800 整行有内容。

### 2. 关于页滚动后卡片与背景同色
- 根因：渐变背景 `alpha` 随 scrollFraction 归零，只剩主题底色；miuix 的 Card 用
  surface 色（白），与 background（247 灰）只差 8，卡片糊进背景。
- 修法：渐变 alpha 设下限（浅色 0.55、深色 0.34），滚动到底仍留一层淡渐变。
- AVD 实测：卡片 (255,255,255) vs 背景 (247,228,240)。

### 3. 版本号 -open 尾缀 → 删掉 open flavor 的 `versionNameSuffix "-open"`。

### 4. 顶栏折叠（重要教训）
- **miuix 折叠是内置行为**：大标题滚动后折叠成居中小标题，GlassTopAppBar 与
  普通 TopAppBar 一致。默认 `MiuixScrollBehavior()` 就够，不要传 canScroll/snap/fling。
- 我上一版加的 `canScroll={true}` + 自定义 spring/decay 是**多余且有害**的
  （改坏了设置页本来正常的吸顶手感）。已全部回退。
- 应用页不折叠的真因：空态走独立 `Box` 分支，那一支没挂 nestedScroll、也没内容可折射。
  已改为**始终用同一个 LazyColumn 承载**（空态作为一个 item），与设置页同构。

### 5. 更新逻辑是空壳（3 个真 bug）
- `AppVersion.parse` 正则把结尾锚死成 `$`，`"1.0.4-open"` 解析失败 → 直接 CheckFailed。
  改为只取前导 major.minor.patch，忽略变体/预发布后缀。
- 删掉 `!currentTagMatched` 短路（当前版本 tag 不在列表里就谎报"已是最新"）。
- 下载 URL 按 `app-${abi}-release.apk` 硬拼，与 CI 产物 `JarPlay-openRelease.apk`
  不符 → 必然 404。改用 `UpdateResult.UpdateAvailable.apkDownloadUrl`（release assets
  的 browser_download_url）。
- `ApkDownloader.installApk` 的 FileProvider authority 写成 `.fileprovider`，而
  manifest 声明的是 `${applicationId}.provider`（filepicker 库的 nnf_provider_paths
  是 root-path，路径够宽）→ getUriForFile 直接抛异常，永远装不上。
- 进度回调在 IO 线程直接写 Compose state → 改为 Handler.post 回主线程。
- AVD 实测：点"检查更新"副标题由默认文案变为「已是最新」，说明请求+比较都通了。

### AVD 验证经验
- 空态应用页正好是复现"玻璃消失"的最佳场景，不需要真的装 jar。
- 判断玻璃条是否渲染：统计底栏区域非背景像素数，比看均值更灵敏。
